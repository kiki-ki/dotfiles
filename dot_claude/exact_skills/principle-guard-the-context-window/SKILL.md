# principle-guard-the-context-window

コンテキストは有限で、セッションの途中では空かない。あふれると推論の質が落ち、要約による情報の欠落が起き、作業が止まる。費用も同じで、利用上限に当たれば作業が止まる。

- 長い出力、スクリーンショット、大きな文書はサブエージェントに読ませ、メインの会話には要約だけを戻す。
- 毎回使うテンプレートや参照はスキルの本文に置く。別ファイルにすると、読むたびにコストがかかる。
- 作業を段階に分けるときは、段階ごとのファイル数とターン数に上限を決める。仕組みそのものが使うコンテキストも勘定に入れる。

## 繰り返し実行するとき

評価や比較のために `claude -p` やサブエージェントを何度も実行するときは、次の順に進める。

1. 実行の回数と費用の見込みを先に示し、ユーザーの合意を取る。
2. 1 件だけ流して、手順と結果の集計が正しいことを確かめてから広げる。
3. 安い確認から進める。静的な確認、発火の確認、差が分からないものだけの比較、の順にする。重い題材は、それに関わるものを変えたときだけ流す。
4. 1 ターンで終わる判定には軽いモデルを使う。何ターンも動く処理は、軽いモデルにしても安くならないことがある。
