# principle-prove-it-works

作業の結果は、本物を直接見て確かめる。間接的な手がかり（ファイルの更新時刻、出力が新しいこと、エージェントの自己申告、キャッシュされたスクリーンショット）から推測しない。間接的な確認は安く見えるが、間違った推測のまま進めたときのコストのほうがずっと大きい。

- プロセスが動いているかは、派生した状態からではなく直接確かめる。
- キャッシュや派生した表現ではなく、実際の値を読む。
- 確認が失敗したら、システムを疑う前に確認の方法を疑う。

確かめた結果（実行したコマンドと出力、読んだ値、diff）をユーザーに見える形で示してから、完了と言う。自明でない確認は、再実行できるスクリプトにする（[principle-build-the-lever](../principle-build-the-lever/SKILL.md)）。
