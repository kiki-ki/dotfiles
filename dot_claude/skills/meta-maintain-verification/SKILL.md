# meta-maintain-verification

アプリが変わると、検証スキルの機能の地図は古くなる。このスキルは、meta-create-verification で生成したスキル（または機能の地図を持つ検証スキル）を今のアプリに合わせる。確かめる単位は機能だ。すべての機能ファイルをソースと突き合わせ、すべての機能を実際に動かす。箇条書きを 1 つずつ確かめるところまではしない。

頼まれていないのに発火したときは、始める前に点検するかどうかをユーザーに聞く。

## 編集してよい範囲

直すのは地図だけで、プロダクトのコードには触れない。編集してよいのは検証スキルのディレクトリ（SKILL.md、features/、スキルが持つ操作用スクリプト）だけだ。

地図に書かれた振る舞いをアプリがしなくなったときは、どちらなのかを区別する。

- 地図が古い: 地図を直す。
- プロダクトが退行した: ユーザーに報告する。地図を書き換えてごまかさない。

## 結果

最後に次のどれかを明言する。

- **clean**: すべての機能をソースと実物の両方で確かめ、直すものがなかった。ブランチも PR も作らない。
- **changed**: 確かめた修正（文書、操作手段、地図）を 1 つの PR にまとめた。
- **blocked**: 確認を終えられなかった、または確かめた修正を安全に出せなかった。何が妨げたかを正確に書く。

## 手順

1. **対象を見つける。** 起動と操作の節、機能の地図を持つ検証スキル（ふつうは `.claude/skills/verify-*/`）を探す。複数あればどれかを聞く。なければ止まり、meta-create-verification で作れることを伝える。
2. **索引を整える。** 地図の README と、同じディレクトリのファイルを見比べ、抜け、余分、重複、リンク切れを直す。
3. **ソースと突き合わせる。** 機能ファイル 1 つにつき 1 体、読み取り専用の Explore サブエージェントを並行に起動する。各サブエージェントには、ソースを読んでその機能がどう動くかを調べさせ、次の形で返させる: 機能の要約、ソース上の入口、地図が古い疑い（引用付き。なければ「なし」）、実物で確かめる手順 1 つ。サブエージェントにはアプリを操作させず、ファイルも編集させない。
4. **結果をまとめる。** すべての機能ファイルについて結果が返ったことを確かめる。重なる手順はまとめ、アプリの状態の数をなるべく減らす。「古い疑い」は抜き取りで確かめる。最近の変更から、地図にないユーザー向けの機能を探す。「地図にない」と言うには、ソースの具体的なパスを示す。
5. **実物で確かめる。** ソースに問題がなくても必ず行う。操作はすべて自分で行い、起動の仕方は検証スキルの Launch 節に従う。すべての機能を 1 回は動かす。途中で何が起きても、次の 3 つを守る。
   - 予想外のことが起きた後は、doctor で確かめてから操作する。最初の操作の前、新しいセッションごと、操作が失敗した後に doctor を実行する。doctor で分からない不具合（プロセスは動いているが UI が固まっているなど）なら、既知の状態に戻すか起動し直す。
   - それまでに取った証拠が、片付けの後も書いた場所に残っていることを実際に確かめる。
   - 失敗した試行が起動したものは、そのたびに片付ける。共有のインスタンスなら、インスタンスではなく試行が残したものだけを片付ける。

   スキルの記述が古いせいで doctor が失敗するなら、それは地図の古さとして扱う。範囲内で直して 1 回だけやり直し、だめなら blocked にする。たどり着けない機能は、必要な前提（認証、権限、OS、外部の状態）と試した経路を書いたときだけ「到達不可」とする。地図にその前提が書かれていなければ、地図の古さとして直す。直した操作手段は、出す前に実物でもう一度動かす。最後の操作が終わったら片付け、証拠以外は何も残さない。
6. **振り分ける。**
   - ユーザー向けの説明が間違っている・足りない: 地図を直す。
   - 振る舞いは正しいのに操作手段が動かない: 操作手段を直す。スクリプトは実行できる状態にし、呼び出し方を本文に書く。
   - アプリの振る舞いが壊れている: 退行としてユーザーに報告し、PR には入れない。
7. **出すか止めるか。** changed なら、確かめた修正を 1 つの PR にまとめる。出す前に、変更したファイルをすべて読み直す。clean か blocked なら PR は作らず、結果と確かめた範囲を報告する。

確かめた機能、たどり着けなかった機能の前提、見つけた古さ、結果は、一時的な場所に短くメモする。コミットはしない。
