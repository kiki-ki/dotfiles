## セッションで実際に使ったスキルとツールに絞る

指摘は、このトランスクリプトで使われたスキル・ツール・MCP を指すものに限る。親が開いてもいないスキルへの推測の振り分けは数えない。スキルが使われたかは、トランスクリプトで次を探して確かめる:

- `SKILL.md` に対する Read、または Skill ツールの呼び出し
- スキルのパスに言及している Agent へのプロンプト
- スキルに書かれたコマンドと一致するツール呼び出し

有効な指摘の形は 2 つ:

- 親がスキルを使い、その本文に本当の穴を見つけた。スキルの該当節に振り分ける。
- スキルが使えたのに、役立つ場面で呼ばれなかった。次は呼ばれるように description を調整する。`tune description: <skill path>` として振り分ける。

上の「呼ばれるべきだったのに呼ばれなかったスキル」は、呼び漏れの典型例だ。`tune description` に振り分ける。使われてもおらず、呼び漏れの候補でもないスキルは捨てる。

見つけた長持ちする学びを列挙する。それぞれ:
- Principle: 逆張りの、または二次的な観察を 1 文で。明らかな学びを言い直さない。その下にあるものを名付ける。
- Evidence: トランスクリプト上の正確な箇所（ターン番号か短い引用。言われたことと、言われなかったことの両方）。
- Routing: 最も関係する既存スキル（トランスクリプトに現れたとおりの `SKILL.md` のパス）、呼ばれるべきだったのに呼ばれなかったなら `tune description: <skill path>`、それ以外なら `new skill: <kebab-name>`。

些細なことは飛ばす。親が従った既存スキルからすでに明らかなことは飛ばす。移ろう実装の詳細（特定の SHA、今のファイルパス、バージョン番号、正確なバイト数）は飛ばす。コードが変わっても生き残る原則とパターンだけを挙げる。
