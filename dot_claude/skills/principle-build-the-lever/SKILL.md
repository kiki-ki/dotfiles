# principle-build-the-lever

自明でない作業は、手でやらずに、それをやる道具を作る。

道具を作ると得をすることが 2 つある。1 つ目に、道具は毎回同じやり方で作業し、何度でも無料で再実行できる。2 つ目に、レビュアーは道具を読んで再実行すれば作業を確かめられる。手でやった変更は、やり直さない限り確かめられない。

道具を作らなくてよいのは、一目で分かる編集が 2〜3 個しかないときだけだ。基準は回数ではなく自明さで、一度きりの作業でも、道具があれば確かめられるようになるなら作る。

- 最初の 1 単位は手でやって手順をつかむ。次に道具を作り、同じ単位に道具を実行して、手でやった結果と diff を取る。道具は何度実行しても安全にする。
- 編集には codemod かスクリプト、繰り返しのファイルにはジェネレータ、分析には sqlite に入れてのクエリ、検証には再実行できるチェックを使う。
- 道具が全単位を一度に処理できるなら、自分で実行する。スクリプトでできる作業をサブエージェントに手で分担させない。
- サブエージェントに作業を配るときは、手順・検証の条件・触ってはいけない範囲を 1 つのスキルに書いて全員に読ませる。そのスキルはサブエージェントが書き込めない場所に置く。
- この原則を使ったなら、diff に codemod・スクリプト・ジェネレータ・委任用のスキルのどれかが入っているはずだ。入っていなければ使っていない。
- 作業がセッションより長く続くなら、道具をコミットする。
- 道具は仕事をこなせる最小のスクリプトにする。フレームワークは作らない（[principle-laziness-protocol](../principle-laziness-protocol/SKILL.md)）。

繰り返す指示を仕組みにする [principle-encode-lessons-in-structure](../principle-encode-lessons-in-structure/SKILL.md) とは別の話で、こちらは目の前の作業を速く、確かめやすくするためのものだ。
