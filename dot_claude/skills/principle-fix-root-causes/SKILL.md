# Fix Root Causes

デバッグでは症状を直さない。すべての問題を根本原因まで辿り、そこで直す。

**なぜ:** 症状への対処は積み重なる。回避策のたびにシステムは推論しにくくなり、本当のバグは残る。根本原因の修正は最初は遅いが、デバッグにかかる総時間を減らす。

**パターン:**
- まず再現する
- 根本原因に当たるまで「なぜ」を繰り返す
- ガードを足さない（クラッシュを黙らせるための nil チェックは症状への対処）
- 回避策を正当化するのに段落ひとつ分のコメントが要るなら、コードが間違っている（直すのはコメントではなくコード）
- 個別の箇所ではなくパターンを確かめる（同じパターンを grep し、全箇所を直す）
- 行き詰まったら計測する。推測しない（ログを足す、実際のエラーを読む）

**再起動で起きるバグ: コードより先に状態を疑う**

「再起動したら壊れる」ときは、まず古い永続状態を疑う: 設定ファイル、キャッシュ、ロックファイル、シリアライズされた状態。状態ファイルを消して挙動が戻るなら、状態の検証を修正の優先事項にする。
