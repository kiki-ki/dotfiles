# principle-guard-the-context-window

コンテキストは有限で、セッションの途中では空かない。あふれると推論の質が落ち、要約による情報の欠落が起き、作業が止まる。

- 長い出力、スクリーンショット、大きな文書はサブエージェントに読ませ、メインの会話には要約だけを戻す。
- 毎回使うテンプレートや参照はスキルの本文に置く。別ファイルにすると、読むたびにコストがかかる。
- 作業を段階に分けるときは、段階ごとのファイル数とターン数に上限を決める。仕組みそのものが使うコンテキストも勘定に入れる。
