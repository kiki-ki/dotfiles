# Subtract Before You Add

システムを発展させるときは、先に複雑さを取り除き、それから作る。

**なぜ:** 複雑なシステムに足すと、複雑さが複利で増える。先に消せばコードが減り、本質的な構造が見え、次の設計が自明になることが多い。既定は引き算。

単純化を継続的な投資にする。見つけたときより、同じかより小さな表面の裏で、少し単純で少し有能な設計にして去る。

**パターン:**
- 構築の前に削除を置く
- 磨く前に削る（品質に投資する前に最小まで持っていく）
- 推測上のエッジケースではなく、観測された使われ方に合わせて設計する
- 仕様が求める以上の推測的なバリデータ・パーサー・ガードを書かない
- プロンプトも単純にする（冗長な指示や過剰なテンプレートを消す）
- 新しい内容のない参照は、スタブとして残さず消す
