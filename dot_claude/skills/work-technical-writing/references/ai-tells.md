# AI っぽい表現の一覧

中身を増やさずに「ちゃんと書いている感じ」だけを出す型。上ほど強い兆候で、「弱い」は他の兆候と一緒に出たときだけ直す。型を消すだけでなく、読み手に伝える事実に置き換える。事実が手元になければ削るか聞く。

- 「A ではなく B」で、誰も言っていない A を打ち消す。読み手が実際に A と思い込みそうなときだけ残す。「単なる設定ではなく、チームの約束です」は「この設定を変えると全員の CI が落ちる」にする。
- 予告と締め。「重要なのは〜」「結論から言うと」「まとめると」「このように」「参考になれば幸いです」「〜を意識することが大切です」。消して主張をそのまま書く。
- 中身のない強調と評価。「重要な」「非常に」「強力な」「シームレスに」「〜を浮き彫りにする」「〜と言えるでしょう」。「開発体験の向上に極めて重要な役割を果たす」は「`make test` が 4 分から 40 秒になる」にする。
- 何をしたかを言わない動詞。「活用する」「実現する」「対応する」「寄与する」。「キャッシュを活用して改善を実現した」は「集計結果を Redis に 5 分置き、応答を 1.2 秒から 0.2 秒にした」にする。
- 名指しのない出典。「一般に〜と言われている」「ベストプラクティスとして」。出典を書くか、理由を添えて自分の判断として書くか、削る。
- ラベルを繰り返す箇条書き（「**速度**: 速度が向上」）。ラベルを消すか、文にしてつなぐ。
- 削りすぎ。体言止めの羅列、`→` や `/` での省略、助詞の脱落。「日付不正 → exit 2」は「日付が不正なら終了コード 2 で終わる」にする。
- 何でも 3 つ、本文が 1 行の節、1 段落で済む内容の見出し分け（弱い）。
- 太字の多用、絵文字、地の文のダッシュ（——）（弱い）。

その文を別のプロジェクトの文書に貼っても通じるなら、この文書について何も言っていない。
