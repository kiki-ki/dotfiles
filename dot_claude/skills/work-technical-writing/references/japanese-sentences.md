# 日本語の文の規則

この一覧は、textlint（SKILL.md の 3 の 1）が拾わないものを中心に書く。textlint が拾うのは、100 字を超える文、読点 4 つ以上、冗長表現（「することができる」など）、二重否定、漢字 7 字以上の連続、感嘆符と疑問符、敬体と常体の混在、ら抜き言葉。

## 文の長さと構造

- 一文に一つのことだけを書く。二つのことを言っている文は切る。目安は 80 字、読点は 3 つまで。
- 逆接でない「が」で文をつながない。「A だが、B」は A と B が対立するときだけ使う。
  - 前: 設定ファイルを読むが、値が不正なら終了する。
  - 後: 設定ファイルを読む。値が不正なら終了する。
- 主語と述語を近づける。長い修飾語は前に、短い修飾語は後ろに置く。
- 修飾語がどこに係るかで二通りに読める語順にしない。「〜ない」「〜だけ」は、係る語の直前に置く。
- 名詞の前に修飾を重ねない。2 つ以上重なったら文を分ける。
  - 前: 多くのチームが導入しているが効果を測れていないという課題を抱える仕組みだ。
  - 後: 多くのチームがこの仕組みを導入している。ただ、効果を測れているチームは少ない。
- 同じ助詞を 1 文の中で続けない（「A の B の C の」など）。

## 冗長な言い回し

- 動作を名詞にしない。「〜の実施」「〜の変更を行う」「〜化を図る」は、動詞で書く。
  - 前: 設定の変更の実施の際は、再起動が必要です。
  - 後: 設定を変えたら、再起動する。
- 「〜という形で」「〜という点で」「〜的な」は、削るか具体的に言う。
- 「〜していく」「〜してまいります」は「〜する」にする。
- 同じ主張を言い換えて繰り返さない。一つの主張は一度だけ書く。
- 丁寧さを積み上げない（「〜させていただきます」の連続）。

## 主語と語

- 誰が何をするかを書く。受け身は、行為者が分からないときか関係ないときだけ使う。
  - 前: 設定値が検証される。
  - 後: `config.Load` が設定値を検証する。
- 事実や結果を主語にして「示す」「もたらす」と書かない。
  - 前: この結果は、キャッシュが効いていないことを示している。
  - 後: この結果から、キャッシュが効いていないと分かる。
- 文脈から明らかな主語（「私たちは」「このシステムは」）を毎文書かない。
- 「これ」「それ」「この」が指すものを一つに決める。迷ったら名詞を繰り返す。
- 同じものは、文書の最後まで同じ名前で呼ぶ。言い換えは、別のものがあるように読ませる。
- 普段使う言葉で書く。日本語で言えるカタカナ語、造語、比喩は使わない。使うなら初出で意味を書く。

## 確かさ

- 本文の根拠で確定していることは言い切る。確かめていないこと、推定、仮定は、その不確実さを残して書く。
- 因果を書くときは、なぜそうなるかを一文で添える。
- 「A ではない」と否定するときは、否定する内容をはっきり書き、根拠を一文添える。
- 「必ず」「すべて」は、本当にそうだと確かめたときだけ使う。

## 表記

- 書き込む先の既存の表記に合わせる。手がかりがなければ次の既定に従う。
- 英数字と日本語の間に半角スペースを入れる。
- 句読点は「、」「。」。
- 形式名詞と補助動詞はひらがなで書く（こと、とき、もの、ところ、ください、いる、みる、など）。
- 数は算用数字で書く。「一つ」「一度」のように、数えていない慣用表現は漢数字のままにする。
- スラッシュで「A/B」とまとめない。「A と B」「A または B」と書く。
